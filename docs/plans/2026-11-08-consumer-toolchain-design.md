# 消费端发布与 Stylelint 18 兼容

目标是让 weapp-vite 使用正式发布的 repoctl 和共享 lint 配置，移除消费端发布补丁，并在严格 peer 安装下保留 CSS、SCSS、Vue 和小程序样式规则。

发布补丁迁回 `@icebreakers/monorepo` 源码：历史源码恢复目录位于 Git 元数据之外，以工作流身份隔离，拒绝符号链接，成功完成 finalize 后才清理；超长发布 PR 按完整条目预算收敛，保留全部包版本和不可变 CHANGELOG 链接，在推送前拒绝无法容纳的摘要；GitHub 错误只输出有界白名单字段并隐藏凭证与提交正文。

Stylelint 18 已获支持的标准配置和排序引擎继续作为运行依赖。SCSS 插件、推荐 SCSS / Vue 配置和 recess 属性组尚未更新 peer 范围：等待上游发布不能解决当前消费端升级，根 overrides 也不能形成独立可安装的发布包。采用构建期打包这些固定上游实现的方案，运行时加载本包预设，保留上游许可证和完整规则；不复制整个插件源码作为新维护分支。

发布包只声明已经兼容的运行依赖。打包测试在隔离消费者中启用严格 peer 检查，执行 CSS、SCSS、Vue、WXSS 的通过、报错与修复场景，同时验证 ESLint 样式桥接和公开类型。发布恢复、超长正文、错误脱敏覆盖真实准备与客户端边界。PR 通过最新 head/base 对应的原生审批矩阵后 squash 合并，正式发布后再更新消费者。

新增发布与预设模块均少于 300 行；现有 `stylelint.integration.test.ts` 仅更新预设路径识别，保持既有集成场景组织，避免将本轮依赖交付扩大为历史测试结构重排。打包上游实现及其传递实现的许可证保存在 `presets/THIRD_PARTY_NOTICES.md`。
